# 我们的池塘：二次开发方案

> 基于开源项目「碧池观鱼」(moli-xia/fishwallpaper) 的调研结论，规划一个有我们自己特色的治愈系池塘壁纸。
> 本文档是唯一决策依据：借鉴什么、自研什么、按什么顺序做、红线在哪里。

---

## 0. 一句话定位

**桌面上的一方活水，想它了就点进去，变成一条鱼游一会儿。**

三个产品原则（所有功能决策的裁判）：

1. **治愈 = 关系，不是画面**：每个功能要么加深「鱼与你的关系」，要么提供「情绪仪式」，否则砍。
2. **一切生物皆代码**：运行时只允许 1 张池底图（自生成）+ 音频，生物全部程序化绘制，Web 包体积红线 ≤ 2MB。
3. **双形态**：壁纸形态（挂机、轻交互）+ 窗口形态（打开来玩、重交互）。玩法突破全部发生在窗口形态，但羁绊数据跨形态共享。

## 1. 合规策略（先于一切技术决策）

原项目**没有 LICENSE 文件**，默认保留所有权利。因此：

| 行为 | 是否可行 |
|---|---|
| 直接 fork 改代码并分发 | ❌ 侵权，禁止 |
| 阅读其源码理解算法，自己重写实现 | ✅ 思想/算法不受版权保护，代码才受 |
| 复用其美术资产（pond.jpg 等） | ❌ 禁止，我们用 AI 自己生成自己的 |
| 借用其功能清单/玩法设计 | ✅ 设计思路不受保护 |

**执行纪律（clean-room）**：
- 参考副本放在 `koi-research/`（只读），我们自己的代码在 `our-pond/`，两目录永不混用文件。
- 借鉴 = 读懂原理（如脊柱链的限位角跟随）后用自己的结构和命名重写，**禁止逐行翻译式拷贝**。
- 视觉走我们自己的方向（见 §5），不克隆它的青碧色池。
- 同步动作：给原仓库开 Issue 询问授权/加 MIT。若作者同意，可解锁「直接借用部分实现」的快车道；不同意也不阻塞本方案。

## 2. 借鉴清单（学什么、为什么值得）

这些是原作被验证过的架构精华，值得照着思路重写：

| # | 借鉴点 | 原作出处 | 为什么值得 |
|---|---|---|---|
| B1 | **脊柱链 + 行波游动** | core.js `updateSpine`/`fishPose`（合计 ~35 行） | 俯视鱼动画的最优解：头引领 + 每节限位角 + 从头传到尾的正弦波。成本低、效果碾压帧动画 |
| B2 | **分层渲染管线** | gl.js `LAYERS` 七层：shadow/under/floaters/surface/airShadow/air/glow | 一张表就定义了池塘的空间语义（池底影→水下→水面浮叶→水面→空中影→空中→发光）。新生物挂对层就有正确遮挡 |
| B3 | **程序化生物贴图（多通道）** | art.js `fishLayers`：albedo/shade/spec/fin 四通道 | 圆柱截面明暗 `sh=.64+.36·√(1-v²)` 是「2D 贴图有体积」的核心戏法；鳞片=错位网格函数 |
| B4 | **深度系统一鱼三用** | scene.js：depth 同时驱动影子偏移/模糊/浓度、水雾混合、绘制排序 | 一条 scalar 撑起整个水下空间感，性价比最高的设计 |
| B5 | **宿主薄壳架构** | JS 核心 + 每平台几百行壳（C#/Swift/Java） | 一份核心，多端分发，包体 ~2MB |
| B6 | **行为系统** | core.js `swim()`：beat-and-glide、随机目标+休息、惊逃、抢食 | 鱼「活着」的全部秘密，~60 行 |
| B7 | **天气=纯数据表** | scene.js `looks`：一种天气一张参数表 | 加天气/季节/皮肤就是加数据，不加逻辑 |
| B8 | **性能纪律** | 质量分档、eco 30fps、`document.hidden` 暂停、canvas 尺寸上限 | 壁纸是 24h 挂机的，这套纪律必须原样继承 |
| B9 | **WebGL2 主路径 + Canvas2D 兜底** | gl.js `createRenderer` try/fallback | 兼容性保险，兜底路径同时是教学/调试路径 |

**明确不借鉴的**：无构建纯 JS 的工程形态（我们要上 TS+Vite）；其具体配色和美术参数（我们做自己的）；其 60 尾上限的图集写法（我们做成可配置）。

## 3. 自研清单（我们的特色，按优先级）

### F1 羁绊系统（被回应感）— 首发核心

鱼有 `familiarity`（0–100），只涨不跌太慢、按天缓慢衰减一点，来源：投喂 +2 / 摸鱼 +1 / 共处时长 +0.1/分钟 / 化身同游 +0.5/分钟。

四档行为（写进 `swim()` 的光标向量，是现有惊逃逻辑的镜像）：

| 档位 | 行为 |
|---|---|
| 0–30 怕人 | 保持距光标的安全半径，受惊半径大 |
| 30–60 好奇 | 在安全距离外悬停「围观」光标 |
| 60–90 亲人 | 绕着光标慢慢画圈 |
| 90+ 知心 | 双击呼唤即到；化身模式下跟队 |

摸鱼反馈：点击命中鱼身（对脊柱段做距离测试）→ 轻摆尾 + 爱心泡泡（glow 层）+ 一声水声。UI 上图鉴面板显示羁绊爱心。

### F2 放灯仪式（夜晚）

- 夜晚（黄昏后）窗口形态出现「放一盏灯」：可选写一句心愿（仅存本地，绝不上传）。
- 灯 = floater + glow 暖光 + 水面倒影拉丝（final shader 里给光源位置加一点法线扰动），随风漂过池塘，在荷叶间停驻或从边缘淡出。
- 灯会累积：你放过的灯会记住，特殊日子（你标记的纪念日）满塘回放。

### F3 化身模式（玩法突破之一，复用度最高）

- 入口：窗口形态点击自己的鱼 →「成为它」。**整条游动/深度/影子系统 100% 复用**，只是把 AI 目标换成玩家输入。
- 操控：光标=目标点（鱼用同一套物理游过去，不瞬移）；按住=加速；双击=冲刺；滚轮=上浮/下潜。
- 联动：羁绊 ≥60 的鱼会自发跟在你身后巡塘（现有邻居逻辑加一个「跟随领袖」权重）；你能顶开鱼食、惊散青鲢、追乌龟。
- 退出：Esc「回到岸边」。壁纸形态禁用化身（输入不可靠），但羁绊成长跨形态共享。

### F4 钓竿玩法（钓宝不钓鱼）

- 窗口形态按住施竿，浮漂落水带涟漪（`drop()` 语义），下沉。
- 池底随时间生成「宝物」：漂流瓶（短句祝福）、星砂、落叶、古钱 → 钓起进收藏架。
- **锦鲤永不咬钩**，只会调皮顶漂（顶漂的是熟人就冒爱心）——保护 F1 建立的情感。
- 青鲢（野生鱼群，与收藏锦鲤分库存储——这个分库设计借鉴原作）可以咬钩：温和的拉扯小游戏（张力条保持绿色区间）→ 起鱼入图鉴 → 放流。星砂可以喂鱼换取限时闪光。

### F5 池塘主题皮肤系统

把原作的 looks 表扩展成「主题包」：水色分级 + 池底图 + 锦鲤色板 + 环境音的组合。首发 2 套自研主题（见 §5），后续可加。这也是我们区别于原作的视觉识别载体。

### F6 状态感知关怀（backlog，M3 后再评估）

- 键鼠活跃度检测：忙时池塘自动安静（涟漪/蝴蝶减少、鱼沉底）；连续空闲 3 分钟 → 蝴蝶来、鱼浮上水面围圈。不弹窗，用池塘的状态说话。
- 番茄钟：专注 25 分钟 → 鱼群聚中央摆庆祝队形 + 一朵荷花绽放。

### 明确不做

- ❌ 实体稀客的立绘/叫声素材（体积红线）；影子鸟这类零成本剪影稀客可作彩蛋
- ❌ 任何账号/云同步（本地优先，分享走导出链接）
- ❌ 喂食打卡推送、红点、签到（与治愈定位冲突）

## 4. 技术架构

### 4.1 工程形态（与原作的差异点）

- **TypeScript + Vite**，零运行时依赖，产物仍是静态 `index.html + js`（保持可丢进 Lively/WE 的性质）。
- 保留 WebGL2 主路径 + Canvas2D 兜底。
- 仓库结构：

```
our-pond/
  core/       模拟：脊柱、行为、羁绊数值（纯 TS，可单测）
  art/        程序化贴图：鱼/鳍/灯/宝物/生物（纯 TS，输出离屏 canvas）
  render/     webgl2.ts + canvas2d.ts，七层管线
  scene/      组合层：天气、季节、生物管理
  app/        UI + 双形态路由（壁纸形态/窗口形态）
  hosts/      平台壳（Phase 后期：WebView2 壳、WallpaperService）
  assets/     仅：池底图（AI 自生成）+ 可选音频 + 图标
```

### 4.2 数据模型

```ts
interface Fish {
  id: string; name: string;
  species: 'koi' | 'silvercarp';   // 收藏锦鲤 vs 野生青鲢分库（借鉴 B）
  palette: number; seed: number;   // 花纹 = 纯函数(seed)，天然支持稀有度与遗传
  size: number; bornAt: number;    // 慢成长 + 满月寿星记号
  familiarity: number;
  marks: Mark[];                   // 手绘花纹
}
```

- 存档：localStorage + 导出/导入；**一条鱼 = 一小段 JSON**，编码进 URL 即可送人（分享功能几乎免费）。
- 存档清洗函数（借鉴 `sanitizeSave` 的防御式写法）是加字段时必须同步更新的固定动作。

### 4.3 平台策略（分阶段，Web 先行）

| 阶段 | 平台 | 方式 |
|---|---|---|
| M0–M3 | Web | 浏览器即玩；Windows 用户经 Lively/WE 设为壁纸（零壳成本） |
| M4 | Windows 独立壳 | WebView2 常驻桌面层（自研壳，参照原作思路） |
| 之后 | macOS / Android | 薄壳（Swift / WallpaperService），视反响排期 |

### 4.4 性能预算（从 M0 就生效）

- 任意帧 ≤ 3ms GPU（核显 1080p@60）；eco 档 30fps；隐藏时暂停；全屏遮挡检测。
- Web 包 ≤ 2MB：池底图 ≤ 800KB、音频可选 ≤ 400KB、代码 ≤ 300KB；CI 加体积检查。
- 粒子类效果（灯、爱心、涟漪）严格限量池。

## 5. 美术方向（我们的视觉识别）

不再走原作的暖青碧色，二选一（推荐 A）：

- **A 青瓷琉璃（推荐）**：冷调青瓷水、更强的折射与光带，锦鲤 + 一两尾金鱼混养。白天治愈感连续性好，放灯在冷色水面上对比更出彩。
- **B 淡彩水墨**：宣纸底 + 墨色锦鲤 + 一点朱砂。程序化更容易（色彩通道少），辨识度极高，雨天做「墨晕开」效果是招牌画面。

池底图用 AI 按选定方向自生成（记录提示词进 `assets/ARTWORK.md`，沿用原作的溯源习惯）。

## 6. 里程碑

| 里程碑 | 内容 | 验收门（过不了不许进下一个） |
|---|---|---|
| **M0 原型**（3–5 天） | 脊柱链游动 + 程序化锦鲤（简化明暗）+ 光标涟漪，网页可玩 | 60fps@核显；丢进 Lively 确认能当壁纸；鱼的动作「读起来是活的」 |
| **M1 池塘完整**（1–2 周） | 自研池底图、水面（涟漪 sim + 焦散 + 折射简化版）、天气、投喂/惊吓、收藏 UI、存档 | 能当日用壁纸长期挂机不发热 |
| **M2 羁绊 + 仪式**（1 周） | F1 羁绊四档 + 摸鱼；F2 夜灯 | 情感验收：会让你主动想再打开看一眼 |
| **M3 玩法**（1–2 周） | 窗口/壁纸双形态路由；F3 化身；F4 钓竿 | 一次 10 分钟的游玩 session 成立 |
| **M4 打磨分发** | 主题皮肤、分享链接、Windows 壳、体积达标 | 陌生人不看文档能装会用 |

## 7. 风险清单

| 风险 | 等级 | 对策 |
|---|---|---|
| 程序化鱼的「美感」达不到原作（原作参数显然调了很久） | **高** | M0 就建立「截图对比迭代」循环；先简后繁（先大色块关系，再鳞片细节）；实在不行降级为更风格化的画法（水墨路线天然免疫此风险） |
| 法律（无 LICENSE） | 中 | §1 的 clean-room 纪律 + 自有美术 + 主动联系作者 |
| 性能（壁纸 24h 挂机） | 中 | §4.4 预算从 M0 生效；低配机早期纳入测试 |
| 范围膨胀 | 中 | 功能全部进本文档分级，未列入 §3 的想法先进 backlog 不动手 |
