# M3 灵性方案：亮度收敛、荷花茎摆、锦鲤灵性、生物美化

> 用户反馈：整体不够生动、没有灵性。画面太亮太晃眼；荷花根本不会动（要有"杆"随水摇摆）；
> 部分小生物仍像 SVG 画的；金鱼不灵动且都一个样；交互反馈廉价。
> 本文承认每个问题的根因，给出任务与验收标准。

---

## 0. 反思：每个问题的技术根因

| 反馈 | 根因（自查确认） |
|---|---|
| 太亮、太晃眼 | 亮度链累计过曝：`bright` 白天 1.04 + `specK` 1.35 + 焦散叠加 + 浅色沙底，四者相乘刺眼 |
| 荷花不会动 | 我只给了 ±0.03~0.12 弧度的"点头"旋转，没有可见的茎——俯视图里花是"贴"在水面上的贴纸，没有"杆撑着花"的结构 |
| 小生物像 SVG | ① 泡泡/水珠/水花冠/莲蓬至今仍是矢量绘制；② 已 AI 化的螺/水黾/虾存在**旋转锚点假设错误**（生成图的头朝向与我代码假设不一致），看起来诡异；③ low 质量生成的精灵偏糊，没有后处理 |
| 金鱼不灵动、都一个样 | ① 体型区间被我压到 0.52~0.86（1.65 倍），视觉上"一个样"；② 行为参数（巡游速度/反应/食量）方差太小；③ 游动曲线太温吞——没有偶发冲刺、急转这类"灵气"动作 |
| 交互丑 | 水花冠是简笔画式的白环+白点；小鱼抢食没有聚群旋涡的"闹感" |

## 开源素材调研结论（回答"有没有开源方案"）

- [Kenney Fish Pack](https://kenney.nl/assets/fish-pack)：**CC0**、120 个文件、含矢量源文件——质量高但风格是**扁平卡通风**，与我们"画意写实"的 AI 素材风格冲突，直接混用会打架。
- [OpenGameArt](https://opengameart.org) 有 "Pond Pals Art Pack" 等池塘生物包，质量参差，许可证需逐个核对。
- **定位决策**：CC0 包作为**设计参考**（姿态/比例/配色学习）与**最终回退**，主力继续用 toapis 生成——只有 AI 生成能保证与现有池底/荷叶/锦鲤风格统一。生图提效手段：提示词加"配套风格描述"、多候选择优、ffmpeg 锐化+对比度后处理。

## 1. Phase L：亮度收敛（立竿见影，先做）

| # | 任务 | 改动 |
|---|---|---|
| L1 | 亮度下调 | `bright` 白天 1.04 → 0.90，傍晚相应下调 |
| L2 | 波光收敛 | `specK` 1.35 → 0.8；sparkle 阈值再抬（更稀有的碎金） |
| L3 | 焦散收敛 | 光网亮度 0.4 → 0.26，tint 降白度 |
| L4 | 水色分级 | 新增径向深浅：中心水色深一档（水体厚度感），边缘浅——顺带完成 M2 遗留的 W4 |

**验收**：白天直视不刺眼；波光从"晃眼"降为"点缀"；截图平均亮度下降 ~15% 且不发灰。

## 2. Phase H：荷花茎摆（"像杆子一样随水摇"）

| # | 任务 | 做法 |
|---|---|---|
| H1 | 茎结构 | 每株荷花加 `stalk`：锚点（水底根）+ 头部摆动位移。摆动 = **弹簧动力学**（角度+角速度，阻尼回正），驱动源三个：风场推力、水花冲击（复用 `splashImpulse`）、波面斜率的持续轻推 |
| H2 | 茎绘制 | 根部到花头画贝塞尔弯曲茎（深绿→浅绿的渐变、S 形弯曲随摆动幅度），花头画在茎端；花苞/半开/盛放三态挂在茎端（现有交叉淡化保留） |
| H3 | 风与冲击联动 | 阵风过境 → 全部花头顺风偏摆后回弹；点击/鱼跃落点旁 → 该花一颤 |
| H4 | 荷叶微升级 | 叶心轻微"顶"一下的浮动幅度加大（对波面的响应更明显） |

**验收**：起风时花头肉眼可见地摇曳；在花旁点击水花，花被打得一颤；没有任何一株花是"静止贴纸"。

## 3. Phase K：锦鲤灵性（重点）

| # | 任务 | 做法 |
|---|---|---|
| K1 | 体型分化 | 体型区间 0.52~0.86 → **0.5~1.3**（2.6 倍差距）；大体型 = 慢而稳重（speedMul × 0.75）、小体型 = 灵活（× 1.25）——大小差异一眼可辨 |
| K2 | 性格方差 | cruise/react/appetite 的随机区间拉大 1.5 倍，出现明显的"慢性子"和"急性子" |
| K3 | 偶发冲刺 | 游荡状态随机触发 0.8s 的小冲刺+急转（灵气的来源：安静的池塘里突然一尾鱼窜一下） |
| K4 | 金鱼变体 | 程序化新增**金鱼**体型：更圆的轮廓+明显更大更飘的尾鳍（贴图参数化，同一套脊柱系统），红/红白/五花三色，与锦鲤混养 |
| K5 | 深度分层 | 每尾鱼有偏好深度带（浅层巡游者持续出尾迹、深层者偶上浮），不再是全池均匀分布 |

**验收**：30 秒观察视频能一眼分辨"大老慢、小机灵、圆金鱼"；至少看到一次偶发冲刺。

## 4. Phase C：生物美化

| # | 任务 | 做法 |
|---|---|---|
| C1 | 旋转锚点审计 | 逐一核对螺/水黾/虾/小鱼生成图的头朝向，修正代码的旋转假设；尺寸对齐真实比例 |
| C2 | 矢量残留清零 | 泡泡（加折射高光）、水珠、水花冠、莲蓬重画——水珠/水花改为 AI 生成（透明底水珠精灵） |
| C3 | AI 重生成提效 | 对不满意的精灵重生成：提示词带全风格上下文（与池底同款画意描述）、每个生成 2 候选择优、ffmpeg 锐化+对比度后处理（仍遵守 low/1K） |
| C4 | 新增乌龟 | 荷塘点题生物：AI 生成背甲俯视图（2 变体），行为=缓慢巡游+定时浮头换气（浮头触发涟漪+泡泡），复用锦鲤脊柱系统游动 |
| C5 | 锦鲤贴图美化 | 鳍/尾的绘制再柔化一档（边缘透明度曲线），游动时的摆尾频率与速度耦合加强 |

**验收**：任意生物与荷叶同框截图，"看不出是程序画的小玩意"；新截图与 M2 对比明显更生动。

## 5. Phase I：交互美化

| # | 任务 | 做法 |
|---|---|---|
| I1 | 水花重做 | 水花冠多层柔边环（3 层不同半径/透明度渐隐）+ AI 水珠精灵替代白点 |
| I2 | 小鱼抢食旋涡 | 投食点的小鱼群聚成绕食点旋转的旋涡状（切向力），持续到食物耗尽——"闹"起来 |
| I3 | 躲避轨迹平滑 | 水黾/虾的受惊移动加缓入缓出，不再瞬移 |

**验收**：交互瞬间的截图无廉价感；投食能看到小鱼旋涡。

---

## 6. 执行顺序与总验收

**L → H → K1~K3 → C1~C4 → K4/K5/C5/I**

总验收门：
1. 白天画面直视 10 秒不刺眼（亮度均值 -15%）
2. 每株荷花持续可见地随水摇曳，风过更明显
3. 30 秒视频能分辨 ≥3 种"鱼格"（大慢/小灵/金鱼），且偶发冲刺出现
4. 全部生物精灵与画风统一，无"SVG 感"残留
5. 回归：帧耗时 ≤ 5ms、清晰度 ≥ 7.8、包 ≤ 2MB（新增资产注意：乌龟 2 张 + 水珠 1 张 ≈ +250KB，如超限则压缩旧图）
