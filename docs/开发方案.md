## 1. 渲染架构（M1 最终形态）

```
┌─ Canvas2D sceneCanvas（离屏，现有 pond2d.ts 演进）─────────────┐
│ 池底图 → 焦散(预乘) → 鱼影 → 底栖生物(螺/虾) → 鱼 → 泡泡      │
│ 注意：荷叶不在此层（荷叶在水面之上，见 pass C）                │
└──────────────────────┬───────────────────────────────────────┘
                       │ texSubImage2D 每帧上传（格式 RGBA8）
┌─ WebGL2 ──────────────▼────────────────────────────────────────┐
│ Pass A 涟漪模拟（1/4 分辨率，RGBA16F ×2 ping-pong）            │
│   drop: h += strength·exp(-d²/r²) 型注入（投食/雨/鱼跃/水黾）  │
│   sim:  v += (avg4-h)·k; v *= damp; h += v                     │
│   normal: 有限差分 → 法线存 ba 通道                             │
│ Pass B 焦散（1/2 分辨率，单纹理）                               │
│   从法线算折射光线的面积差分 → 池底亮纹，叠加太阳强度/颜色      │
│ Pass C 水面合成（全分辨率 → 屏幕）                              │
│   折射：sceneUV + normal.xy · strength 采样 sceneCanvas         │
│   基线波：两层滚动噪声法线（微风，不受涟漪影响）与涟漪法线混合  │
│   高光：Blinn-Phong(太阳/月亮方向) → 波光                       │
│   深水色：距中心/边缘的水体吸收色调                              │
│   之后叠加：荷叶层（CPU 提交四边形+自身浮动/影子）→ 空中层      │
└─────────────────────────────────────────────────────────────────┘
```

降级链：WebGL2 ✗ → 尝试 WebGL1+扩展 → 仍 ✗ → 现有 Canvas2D（M0 画质，涟漪圈保留）。
在设置里暴露"水面质量：模拟/简化/关闭"。

## 2. M1a 水活：任务分解

### T1 新池底图（无波纹无荷叶版）
- `assets/`：toapis 重生成（16:9、**1K、quality low**——只画水底材质，1K 足够；提示词在现有 ARTWORK.md 基础上删除波纹/光斑/荷叶/荷花要素，强调"flat underwater ground, no surface, no waves, no light patterns"）。
- ffmpeg 压缩到 2048px JPEG ≤ 300KB。
- 验收：放大看无明显波纹/光斑结构；中心 80% 均质；与 shader 波纹叠加不穿帮。
- 保留旧图用于"简化"画质档。

### T2 `src/render/gl/common.ts` — WebGL 薄封装
- `createGL(canvas)`：`getContext('webgl2', { alpha:false, antialias:false, depth:false, stencil:false, powerPreference:'low-power' })`。
- `compile(vs, fs)` / `program()` / `fbo(w,h,internalFormat,format,type)` / `quadVAO()`。
- **兼容性关键**：RGBA16F 渲染目标需要 `EXT_color_buffer_float`；不可用则降 RGBA8（高度/速度编码进 [0,1] 区间，精度损失可接受——涟漪是相对量）。
- 验收：`glslVersion 300 es` 的空 pass 能画清屏。

### T3 `src/render/gl/ripple.ts` — 高度场模拟（借鉴 evanw）
```ts
class RippleSim {
  constructor(gl, w, h)            // 1/4 分辨率，双 FBO
  drop(x, y, radius, strength)     // 高斯包络注入（UV 坐标）
  step(dt)                         // 固定步长 1/60，最多补 3 步/帧
  normalTex(): WebGLTexture        // 含法线的当前纹理
}
```
- shader 三件：`FS_DROP`（注入）、`FS_SIM`（更新，边界用 clamp-to-edge 天然形成岸壁反射）、`FS_NORMAL`（差分法线）。
- 参数初始值：`k=2.0`、`damp=0.995`、注入 `strength·exp(-d²/r²)`——均为 evanw 验证值，之后再调。
- 验收：点击水面，涟漪扩散-反射-衰减全程可见且稳定（不爆、不振荡不消失）。

### T4 `src/render/gl/water.ts` — 合成 pass
- 输入：sceneCanvas 纹理、ripple.normalTex、时间、太阳参数（方位/颜色/强度）、`uWaveAmp`。
- 基线微风波：两张滚动 value-noise 法线（JS 生成 256² 噪声纹理上传，双采样叠加），与涟漪法线 `mix`。
- 折射偏移上限 8-14px（原作区间），避免池底图采样出界（clamp + 边缘渐隐）。
- 高光：`pow(max(dot(N, H), 0), 180-400)`，太阳暖/月光冷由 look 传入。
- 验收：静止时水面仍有微波光；点击处池底发生可见折射扭曲；高光沿太阳方向闪烁。

### T5 `src/render/gl/caustics.ts` — 焦散 pass（借鉴 evanw 面积差分）
- 原理：对每个池底点，取其折射光线落点处的"面积压缩比"作为亮度（光的能量守恒 → 收缩处亮）。
- 1/2 分辨率单纹理，动画靠法线场随时间变化自然演变；叠加太阳高度系数（正午强、晨昏弱、夜里无）。
- 验收：池底有缓慢游动的亮纹网络；鱼身上也叠加（在 sceneCanvas 上以第二 pass 或 CSS 预乘进鱼绘制——选实现简单的：鱼绘制时乘焦散采样，见 T6）。

### T6 渲染器接线 `src/render/renderer.ts`（重构）
- `Renderer.render(pond, look, dt)`：
  1. `scene2d.render(...)`（现有 pond2d 改名收编，鱼绘制时可选叠加焦散强度参数）
  2. `gl.sceneTex ← sceneCanvas`（texImage2D）
  3. `ripple.step` → `caustics.render` → `water.render` → 屏幕
- 事件桥：`pond.events` 与 app 层的交互统一转成 `ripple.drop` + 粒子（见 T7）。
- 验收：60fps@1080p 核显（性能面板计时 ≤ 3ms GPU）；黑屏 3s 无 WebGL 上下文丢失。

### T7 水面粒子 `src/render/particles.ts`
- 水珠（抛物线、落水注入 drop + 二次小圈）、水花冠（环状贴图，程序化）、雨滴（后续天气用）。
- 限量池 ≤ 128；`eco` 档减半。
- 验收：投喂出水花；水珠落回水面有第二圈涟漪。

### T8 鱼尾迹与鱼跃 `src/core/jump.ts`
- 尾迹：`pond.step` 里，`depth < 0.22 && v/L > 0.45` 的鱼每 0.14s 在头前注入 `drop(x, y, 3.2·scale, 0.04·k)`（原作验证参数）。
- 鱼跃事件：状态机 `surface → airborne(0.6s 抛物线, depth<0, 绘制加高光+水珠拖尾) → dive(水花冠+大 drop)`；触发：进食后 8% 概率 / 清晨活跃时段加权。
- 验收：一段完整的跃-空-入水编排，落水处荷叶若在溅落半径内则叶面生成水珠（M1b 联动接口预留：`onSplash(x,y,r)` 回调）。

## 3. M1b 植物活：任务分解

### T9 程序化荷叶 `src/art/lily.ts`
- `lilyPadSprite(variant, size)`：径向叶脉（极坐标线束）、随机缺口角、杯状明暗（中心亮缘暗+防水高光）、边缘微卷。3-4 变体缓存。
- 荷花 `lotusSprite(openness, variant)`：8-12 瓣独立旋转的分层绘制；`openness∈[0,1]` 控制瓣张角与露出高度；花苞/盛放/莲蓬三形态插值。
- 验收：视觉上是"画出来的荷"而非贴图感；4 个变体并排不重复。

### T10 荷叶状态机 `src/core/plants.ts`
```ts
interface Pad {
  x, y: number;            // 世界坐标（漂移用绝对坐标）
  r: number;               // 半径
  rot, rotV: number;       // 旋转与角速度
  variant, age: number;    // 生长 0..1（新叶从卷叶展开）
  health: number;          // 枯黄 0..1
}
interface Lotus extends Pad-like { openness, phase: 'bud'|'bloom'|'seedpod'; }
```
- 更新：漂移 = 风 × 阻尼；旋转慢漂；`age` 按真实时间增长（2-3 天长成）；`health` 随季节。
- 荷花 `openness` 按当日时刻：6:00 全开 → 15:00 渐合 → 夜闭合（插值曲线，非开关）。
- 遮荫区：`pond.obstacles` 变为 `shadeZones`（**不再阻挡游动**，改为目标点偏好：正午 `pickGoal` 对叶下位置加分）。
- 验收：叶缓慢漂移旋转；清晨花开午后合；正午鱼群聚集叶下（截图验证）。

### T11 荷叶绘制与遮挡（water.ts 扩展）
- 荷叶在 Pass C 之后按 CPU 提交的四边形绘制（含自己的浮动量：采样 ripple 在叶心的等效高度近似——CPU 侧读取该点最近 drop 强度，或简化为正弦相位；取实现简单者）。
- 叶影：太阳方向偏移 `padR × (0.3 + sunElevK)` 的暗色椭圆，画在 sceneCanvas（水下层）——影随时间转。
- 水珠：T7 水珠落在叶面（点在叶圆内）时改变归属为"叶面水珠"：滚动（沿叶面斜率）、合并（两珠距离 < r 和）、滚出叶缘 → 转回水珠落水。
- 验收：鱼从荷叶下游过被遮挡正确；叶影方向早晚不同；水珠在叶上滚动合并。

### T12 存档扩展
- `pads/lotus` 数组入存档（位置/年龄/健康度）；`sanitize` 兼容旧档（无字段时播种初始布局）。
- 验收：刷新后荷叶位置与生长进度保留。

## 4. M1c 光活：任务分解

### T13 太阳轨迹 `src/core/sun.ts`
```ts
interface SunState {
  elevation: number;      // 0..1（高度角归一）
  azimuth: number;        // 弧度（东→南→西）
  shadowDir: [number, number];
  shadowLen: number;      // 相对长度 0.3..3（晨昏长正午短）
  color: [number, number, number];   // 色温
  intensity: number;      // 焦散/闪光系数
  phase: 'night'|'dawn'|'day'|'dusk';
}
sunState(date: Date, latitude = 32): SunState
```
- 简化太阳模型：按日期算赤纬（±23.4°正弦），按时角算高度角/方位角；不做天文级精确，视觉连续即可。
- 夜间切月相：`moonPhase(date)` 0..1，月盘贴图程序化（亮斑+相位遮罩）。
- 验收：`sunState` 单元断言（冬至/夏至/正午/日出时刻的 elevation 单调性）；连续拖动系统时间画面平滑无跳变。

### T14 look 系统重构 `src/core/looks.ts`
- 把现有 `nightK` 单参数换成 `Look { sun: SunState; mist; fireflyK; vignette; … }`，water/caustics/renderer 全部消费它。
- 清晨薄雾：全屏低透明度白雾 + 露珠彩蛋（叶面随机生成晨露）。
- 季节：`season(date)` → 荷叶 health 增速、荷花开花概率、落叶/结冰调色。
- 验收：同一屏在 6:00 / 12:00 / 18:30 / 22:00 的四张截图光影差异明显且合理。

## 5. M1d 生态：任务分解

### T15 小鱼群 `src/core/minnow.ts`（借鉴 boids 三力）
- `MinnowSchool`：15-25 尾，`cohesion/alignment/separation` 三力 + 惊吓场（锦鲤 60px 内 `v>` 阈值时炸群）+ 觅食碎屑（投喂后 30% 食物标记为碎屑，小鱼优先）。
- 贴图：单张银色小鱼（程序化，透明感 + 侧面高光），批量绘制（同色 batch），尺寸 8-12px。
- 验收：群游有流体感；锦鲤冲过时炸开 3s 后重聚。

### T16 水黾 `src/core/strider.ts`
- 水面层生物：位置在"水面平面"，移动时每 0.2s 注入微 drop（半径小强度低）+ 腿下凹坑贴图（暗色小点）。
- 行为：巡逻 + 被惊时连跳（每次跳=一次位移+drop）。
- 验收：水黾滑过处留下一串可见小涟漪——水面系统的活广告。

### T17 底栖生物 `src/core/critters.ts`
- 螺蛳：贴底 2-5px/min 的爬行（随机路径+边界回转），偶尔上叶梗；焦散响应。
- 青虾：半透明，弹退移动（蓄力-弹射-滑行），食物吸引。
- 验收：镜头拉近能看到螺在动（慢但有）；虾受惊弹退。

### T18 泡泡与浮萍
- 泡泡：深水鱼随机呼出，上浮加速，到水面 `drop(strength=0.02)` + 破裂微光。
- 浮萍：粒子池，风与涟漪场推动（CPU 读 ripple 近似），聚在静水区；锦鲤啄食（游过即减少）。
- 验收：两者都与水面系统正确联动。

### T19 体型修正
- 锦鲤 `size` 分布下调 15%（0.62+r*0.34），新鱼出生尺寸减半再成长。
- 验收：大小鱼同屏层次分明。

## 7. 注意事项（红线与坑）

1. **许可证**：Shadertoy 禁抄；GPL 禁抄；evanw 借鉴后保留版权声明；碧池观鱼代码隔离（koi-research/ 只读）。每次 PR 自查引用来源。
2. **浮点纹理兼容**：WebGL2 渲染到 RGBA16F 需 `EXT_color_buffer_float`；部分低端 GPU/远程桌面没有。**必须**实现 RGBA8 编码降级（h,v 映射到 [0,1]），否则黑屏。
3. **上下文丢失**：壁纸长期挂机，GPU 驱动可能回收上下文。监听 `webglcontextlost`（阻止默认、停渲染）与 `webglcontextrestored`（重建全部资源）。原作有此处理，必做。
4. **texImage2D 每帧上传**是最大的 CPU-GPU 同步点。优化顺序：texSubImage2D 复用 → ` PremultipliedAlpha` 一致（sceneCanvas 用 `alpha:false` 上下文避免混合错误）→ 仍超预算则生物层迁 WebGL 绘制。
5. **时间**：全部动画用 `performance.now()` 相对时钟；`Date` 只用于太阳/季节/花开合（走真实世界）。系统休眠恢复的大 dt 一律钳到 50ms；太阳跳变无所谓（本来就是小时级）。
6. **多显示器/DPI**：Lively 每屏一个实例，`devicePixelRatio` 上限 2 保持；resize 时全部 FBO 重建（记得 delete，泄漏会崩驱动）。
7. **存档迁移**：每加字段就改 `sanitize`，旧档必须能无感升级——M1b T12 是第一次演练。
8. **调试工作流**：保留 `?debug=1` 句柄，新增：`?t=HH:MM`（伪造时间驱动 look，用于快速验收晨昏夜）、`?gl=0`（强制降级路径）。每次视觉改动存对比截图到 `docs/progress/`。
9. **范围纪律**：M1 只做列出的任务；青蛙/蜻蜓/翠鸟/音频全部推 M2。每完成一个任务跑一次 `npm run check && npm run build`。
10. **壁纸宿主输入差异**：Lively 需手动开鼠标转发；交互（投喂/惊鱼）必须保证在无输入环境下系统依然自洽（生物有自己的日程）。
