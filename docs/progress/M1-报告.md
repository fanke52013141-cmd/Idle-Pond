## 事故记录 2：首版"贴图感 / 丑 / 无动态"（用户第二轮反馈，已修复）

对照原项目复盘出的根因与修复：

1. **"美"的来源被砍了**：原作七成观感来自带微妙焦散光斑与苔藓质感的 AI 池底画，
   我为上水面系统把池底洗成了素面 → 重新生成带回焦散光斑的丰富版（2K/low，479KB）。
2. **矢量圆片当荷叶 = "贴图感"**：程序化矢量叶再怎么画也是扁平贴纸。
   → 荷叶×2、荷花改用 **AI 生成的透明底 PNG 精灵**（画笔质感 + 真实水珠，rgba 已验证），
   保留浮动/摇摆/影子/健康度滤镜；加载失败自动回退程序化版本。
3. **微波法线偏置 bug**：shader 里 `(rg 之和 - 2.0)` 应为 `- 1.0`，零点错位导致
   水面整体单向平移而非波动 → 修正后微波真正起伏；波幅 0.35→0.52、滚动提速。
4. 波光高光瓣收宽（pow 260→130）、强度提升；新增**风致微涟漪**（0.5-1.6s 随机点），
   静止画面也有水面生命。
5. 鱼的深度雾 0.28→0.22（更透亮）。

效果：清晰度 4.45 → 7.39 → **7.82**；帧耗时 4.99ms（软件渲染实测）。
默认加载 1.73MB（降级大图按需拉取），红线 2MB 内。

## 事故记录 1：首版"全页模糊"（用户反馈，已修复）

- **根因 1（主要）**：场景离屏画布按 CSS 分辨率建（1600×900），GL 输出画布按 DPR 2 建（3200×1800），
  所有水下内容被软放大 2 倍。用户的屏幕是 200% 缩放，模糊非常明显。修复：场景层与输出层同分辨率
  （DPR 封顶 2，绝对上限 2560×1440）。清晰度指标（640 宽灰度 |dx| 均值）4.45 → **7.39（+66%）**。
- **根因 2**：池底图首版按"能省则省"用了 1K 生成，本身偏软。重新以 **2K/low** 生成（全屏背景属于
  "有必要用 2K"的场景），提示词补强沙纹/卵石细节，424KB。
- **根因 3**：焦散第一版强度过高，像一层白纱洗掉对比度。阈值/权重回调（0.62→0.4 强度、阈值 0.68）。
- 代价：全分辨率场景上传后帧耗时 5.63→7.72ms（软件渲染实测），仍在预算内；真机 GPU 更快。

## 已落地（对照开发方案 T1-T19）

- **水面系统**：WebGL2 高度场涟漪模拟（RGBA16F ping-pong，含 RGBA8 编码降级）、折射采样、
  双层可平铺噪声微风、太阳/月亮镜面波光、焦散（拉普拉斯聚焦 + 细密光网，内联合并实现）、月影与暗角。
- **植物系统**：13 片程序化荷叶（叶脉/缺口/杯状明暗/防水高光，4 变体 × 健康度）+ 3 株荷花
  （苞/盛/莲蓬三形态、晨开午合的连续开放度、随风点头）；叶影方向/长度随太阳轨迹变化；
  水珠落叶面滚动、滚出叶缘消失；荷叶为鱼的遮荫偏好区。
- **光活**：太阳赤纬+时角模型按真实时钟（北京经度修正）全天连续输出；`?t=HH:MM` 可驱动任意时刻；
  清晨薄雾、季节健康度已接（冬季荷叶偏黄）。
- **生态**：18 尾银鱼 boids 群（锦鲤冲过炸群、抢食老化碎屑）、3 只水黾（滑行压涟漪、受惊连跳）、
  3 只螺蛳（贴底慢爬、吐泡泡）、3 只青虾（弹退移动）、泡泡（深水鱼/螺呼吸、破裂出微涟漪）、
  46 点浮萍（漂移、被锦鲤啄食后缓慢复壮）；锦鲤体型下调至 0.52–0.86。
- **鱼跃**：JumpSystem 完整编排（上浮→破水水花→空中弧线覆盖层绘制→入水大水花+涟漪），
  清晨概率加权，冷却 14–32s。
- **存档**：localStorage v1（鱼群/荷叶/荷花/设置），清洗函数 + 旧档兼容默认值。

## 过程中修掉的坑

1. 涟漪模拟 float 路径下法线写入的字符串替换失效 → 显式分支。
2. 噪声纹理不可平铺 → 焦散出现网格接缝 → 重写为周期环绕的 value noise（双八度）。
3. 焦散第一版过白过粗 → 阈值/权重重调 + 细节倍频。
4. **宿主隐藏时 innerWidth 可能为 0** → 0 大小画布 → resize 守卫 + visibilitychange 重排
   （对 Lively 最小化场景同样关键）。
5. 截图管线在隐藏面板下不可靠 → 验收改用「渲染后画布 toDataURL 拉回本地」的通道。

## 已知边界（下一阶段）
